--------------------------------------------------------------------------------
4.1  public.handle_new_user() -> trigger
--------------------------------------------------------------------------------
  Bahasa    : plpgsql
  Keamanan  : SECURITY DEFINER, SET search_path = ''
  EXECUTE   : postgres, service_role  (anon & authenticated DI-REVOKE)
  Dipakai   : trigger on_auth_user_created

  Fungsi: membuat baris profil public.users di transaksi yang SAMA dengan
  insert ke auth.users. Kalau gagal, signup ikut rollback -> tidak ada akun
  yatim (orphan) saat NIK duplikat.

  Alur:
    1. Ambil nik & full_name dari new.raw_user_meta_data (trim, nullif kosong).
    2. nik NULL atau tidak cocok ^[0-9]{16}$  -> raise 23514
       "NIK harus berupa 16 digit angka"
    3. full_name NULL -> raise 23502 "Nama lengkap wajib diisi"
    4. INSERT users (id, nik, full_name, email, role) dengan role
       DI-HARDCODE 'user'::public.user_role.
       -> role SENGAJA tidak dibaca dari raw_user_meta_data, karena isinya
          apa pun yang dikirim client lewat signUp(options.data);
          membacanya = lubang privilege escalation.
    5. Handler unique_violation: kalau constraint = users_nik_key ->
       raise 23505 "NIK <nik> sudah terdaftar", selain itu re-raise.

--------------------------------------------------------------------------------
4.2  public.handle_user_email_change() -> trigger
--------------------------------------------------------------------------------
  Bahasa    : plpgsql
  Keamanan  : SECURITY DEFINER, SET search_path = ''
  EXECUTE   : postgres, service_role  (anon & authenticated DI-REVOKE)
  Dipakai   : trigger on_auth_user_email_changed

  Fungsi: sinkronisasi public.users.email saat email diubah lewat Supabase
  Auth. Tanpa ini kolom email di profil jadi basi permanen karena
  public.users.email adalah duplikat dari auth.users.email.
  Isi: UPDATE public.users SET email = new.email WHERE id = new.id;

--------------------------------------------------------------------------------
4.3  public.nik_available(p_nik text) -> boolean
--------------------------------------------------------------------------------
  Bahasa    : sql
  Keamanan  : SECURITY DEFINER, STABLE, SET search_path = ''
  EXECUTE   : anon, authenticated, postgres, service_role  (SENGAJA publik)
  Endpoint  : POST /rest/v1/rpc/nik_available

  Isi:
    select p_nik ~ '^[0-9]{16}$'
       and not exists (select 1 from public.users where nik = p_nik);

  Alasan ada: RLS hanya mengizinkan user membaca barisnya sendiri, jadi form
  signup tidak bisa mengecek ketersediaan NIK lewat SELECT biasa. Error dari
  dalam trigger signup sampai ke client sebagai 500 opaque, jadi pesan yang
  bagus harus datang dari pre-flight check ini. Unique index users_nik_key
  tetap jadi penjaga sebenarnya. anon harus bisa memanggil karena form signup
  perlu cek NIK sebelum akunnya ada.

5. TRIGGER
================================================================================
  on_auth_user_created
    AFTER INSERT ON auth.users FOR EACH ROW
    EXECUTE FUNCTION public.handle_new_user()

  on_auth_user_email_changed
    AFTER UPDATE OF email ON auth.users FOR EACH ROW
    WHEN (old.email IS DISTINCT FROM new.email)
    EXECUTE FUNCTION public.handle_user_email_change()

  Tidak ada trigger di tabel schema public.
